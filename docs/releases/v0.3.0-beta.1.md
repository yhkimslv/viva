# VIVA 0.3.0 beta 1 team preview

**User guides:** [English](https://github.com/yhkimslv/viva/blob/main/docs/user-guide.en.md) · [한국어](https://github.com/yhkimslv/viva/blob/main/docs/user-guide.ko.md). Follow the on-screen steps from installation through GitHub login and your first clone.

Install VIVA, clone a GitHub project, and start working with your team. No Node.js, npm, or terminal commands are needed. **Git must be installed separately**; VIVA provides graphical installation instructions and a screen for setting your commit author name and email.

**This is an unsigned/unnotarized team preview.** The macOS app uses an ad-hoc signature only, without Apple Developer ID signing or notarization. The Windows installer has no publisher certificate. Your OS may warn about or block these files. Devices that require trusted publisher signatures cannot use this preview.

## Installation and OS warnings

### macOS

1. Open the DMG for your computer and drag **VIVA** into **Applications**.
2. Open VIVA from Applications.
3. If macOS reports an unidentified developer or missing notarization, confirm that you downloaded the intended release and decide whether you trust it. Where permitted, use the per-app approval in **System Settings → Privacy & Security**. Follow [Apple’s official guidance](https://support.apple.com/en-us/102445).

### Windows

1. Open `VIVA-0.3.0-beta.1-windows-x64-setup.exe`.
2. Choose an installation folder and complete the wizard. It installs for the current user without requesting administrator elevation.
3. Open **VIVA** from the desktop or Start menu.

Windows may show an unknown-publisher warning. If **Smart App Control** or an organization policy blocks installation or launch, contact your administrator rather than disabling security protections. Smart App Control does not support exceptions for individual apps, so affected devices need a signed distribution. [Microsoft’s official explanation](https://support.microsoft.com/en-us/windows/security/threat-malware-protection/smart-app-control-frequently-asked-questions)

## Installing Git for the first time

VIVA displays installation instructions if Git is missing. Skip this step if Git is already available.

- **Windows:** download the installer from [Git for Windows](https://gitforwindows.org/) and install with the default options. Keep the default PATH option so applications such as VIVA can find Git, then quit and reopen VIVA.
- **macOS:** on [Apple Xcode Resources](https://developer.apple.com/xcode/resources/), select **Additional tools → View downloads** and sign in with your Apple Account. Download **Command Line Tools for Xcode** compatible with your macOS version, open its DMG, and run the PKG installer inside. A paid developer membership is not required.

After installation, select **Check for Git again** in VIVA. These steps use installation wizards and app buttons; no terminal commands are required.

## Your first project

1. Before cloning a private repository, select **Connect GitHub → Login with GitHub** and complete the browser approval with your own account. This release uses the original project’s OAuth app, **Git Abstraction Tool — Sean Lee (`98sean`)**, which requests the broad `repo` permission, including read and write access to private repositories your account can access. Check the app and permissions before approving. [GitHub’s scope explanation](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/scopes-for-oauth-apps)
2. Select **Clone from GitHub**, enter the team repository’s HTTPS URL, and choose a parent folder and a new project folder name. Select **Clone and open**. Public repositories can be cloned without login; private repositories require a connected account with access.
3. In **Project Settings → Commit author**, check your name and email, then select **Save for this project** if needed. This changes only that project’s local Git settings. The information appears in future commits and uploaded history, so you may prefer your GitHub private email address.
4. Choose a work branch and save your changes. Create, review, and merge pull requests on GitHub. **Lead dashboard** provides a read-only view of PRs, review requests, CI, and assigned issues.
